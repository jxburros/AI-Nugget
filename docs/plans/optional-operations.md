# Plan: optional operations beyond text chat

Status: proposed, not implemented. Requested 2026-10-27 as audit item 13.
The provider/cloud work in 0.7.5 is the foundation, not completion of this plan.

## Goal and boundaries

Expose reusable provider execution contracts for media, documents and retrieval
primitives while preserving a small, zero-runtime-dependency, isomorphic core.
Apps retain prompts, model selection, persistence, indexing, retrieval strategy,
UI, approvals and pricing tables. Do not build a RAG framework or media editor.

Every module must pass AGENTS.md's admission test and use the same policy,
KeySource, authorization/transport, timeouts, redaction and telemetry as chat.
No direct provider fetch from a public module that bypasses those controls.
Provider support must be documented per operation/model/protocol, not inferred
from a chat profile. Keep existing exports and call behavior compatible.

## Milestones and proposed contracts

| Order | Module / contract | Initial provider coverage | Acceptance criteria |
|---|---|---|---|
| 1 | Internal governed-operation runner; typed `BinaryInput`/`FileReference`, operation capabilities and usage | Existing chat/embed adapters first | One redacted record per operation, abort/retry parity, no Node APIs or new runtime dependencies, unchanged existing tests |
| 2 | Rich chat parts: URL images, uploaded files/PDFs, audio and video references | OpenAI-compatible APIs, Google, Anthropic; Meta when its profile lands | Correct MIME/source mapping; unsupported parts fail explicitly; size limits; lossless replay; no raw media in telemetry |
| 3 | `images.generate` / `images.edit` via an optional images import | OpenAI, Meta Muse Image, compatible services with documented endpoints | Multipart/masks where required; generated bytes or provider URLs; usage; cancellation; no automatic file downloads |
| 4 | `audio.transcribe` / `audio.speak` and a separate realtime session contract | OpenAI, Mistral/Voxtral; Meta Voice for transcription only | Binary/multipart upload, timestamps/diarization where supported, streamed audio chunks, bounded session teardown and explicit protocol differences |
| 5 | `documents.extract` | Mistral OCR/document APIs; compatible document providers | Page/block geometry, confidence and structured output preserved; validate parsed output before consumption |
| 6 | Extend embeddings and introduce `rerank` | Native Google embeddings, Cohere, Voyage and documented compatible endpoints | Text/multimodal input capability distinction, input-order and vector validation, rerank indices/scores validated, no vector-store ownership |
| 7 | Files, batches/background jobs, token counting, cache references | OpenAI/Anthropic/Google and other documented implementations | Typed submit/poll/cancel states, explicit expiration/retention, bounded polling, no hidden paid retries or automatic uploads |
| 8 | Specialized media extension points | Meta SAM segmentation; documented video/media-job services | Typed geometry/job results, cancellation/expiry, distinct unsupported-operation errors; avoid flattening every task into chat |

Suggested optional imports are `/images`, `/audio`, `/documents` and `/retrieval`.
Choose names only after bundle/export tests demonstrate unused modules stay out
of browser and worker bundles. Realtime may need an injected WebSocket transport;
do not add a Node WebSocket package to core. Operation methods in this table are
design proposals, not existing public APIs.

## Dependencies and design decisions

1. Extract a governed operation runner without changing existing call ordering.
   It needs per-operation policy identities and replay-safe retry rules. Uploads,
   job submission and realtime session creation must distinguish idempotent retries
   from requests that may incur duplicate work or cost.
2. Define input ownership: bytes/Blob/stream versus uploaded provider reference;
   URL inputs are sent to providers only when explicitly supplied by the caller.
   No library-side URL fetch or persistence by default.
3. Define results with discriminated content parts, usage, source provenance and
   provider extensions. Keep opaque replay state separate from display output.
4. Extend capabilities per operation/model, with explicit unknown/unsupported
   states. Do not silently replace schema enforcement or generated media with text.
5. Support caller-supplied validation for machine-consumed JSON/geometry and
   validate indices/vector dimensions inside the transport contracts.
6. Design bounded jobs/sessions separately from single responses: cancellation,
   deadlines, reconnect/resume, completion/partial/failure, expiration and billing
   metadata. Persistence and scheduling belong to the app.

Meta's provider/profile work from audit item 4 remains a separate prerequisite
for Meta operation adapters. The cloud/profile release does not claim that work
is complete. Likewise, broader Google Interactions and Anthropic version migration
remain separate from this plan.

## Validation and rollout

- Contract fixtures for each protocol: success, invalid content, authorization,
  limits, cancellation during upload/download, truncated streams, abandoned
  iterators, malformed multipart, retries and telemetry/credential redaction.
- Run the same applicable suite in Node and Chromium; bundle optional imports
  in the existing worker and Next.js integration starters.
- Test compatibility against a packed artifact and generated vendor copy.
  Add one concrete consumer use case before declaring an operation stable.
- Keep live smoke tests manual/env-gated. Use small test inputs and explicit
  provider/model selection; missing credentials are a recorded skip.
- Publish a per-operation verification matrix: fixture-tested, live-tested with
  date/model, configuration-only, unsupported. Update it when evidence changes.
- Land milestones in separate reviewable PRs. Start with runner/contracts, then
  one provider per operation, then compatible provider expansion and adoption.

## Review checkpoints

Before each milestone, review its public types, admission-test rationale,
provider endpoint evidence, expected bundle effect, retry/cost semantics and
first consumer. Completion requires generated artifacts, migration notes,
contract/browser tests and honest live-test status. No dates are promised until
the contracts and first integration have been reviewed.
